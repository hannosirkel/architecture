# 006. Generate Habit Hooks configuration with an explicit `files` list

- **Date:** 2026-08-21
- **Status:** accepted

## Context and problem statement

Habit Hooks reads configuration only from inside a project, so every repository
needs a `.habit-hooks/config.toml`. The obvious content is one line naming the
plugins, which is what `habit-hooks init` writes.

Verification against version 1.3.1 found that this is not enough.

## Considered options

- Ship `habit-hooks init`'s output: `plugins = [...]` and nothing else.
- Generate the file with an explicit `files` list and per-sensor overrides.
- Add `jscpd` as a devDependency to every repository so the default works.

## Decision

Generate `.habit-hooks/config.toml` from the catalogue, always with an explicit
`files` list, and disable `jscpd` in repositories with no npm project.

## Rationale

Three observations force it.

**A `generic`-only config scans nothing and reports success.** The `generic`
plugin declares no `files` of its own; the language plugins do. A repository
whose declared languages bring no plugin therefore prints:

```text
habit-sensors: no [files] are configured — nothing scanned
✅ Habit Hooks: automated checks passed.
```

A green tick for scanning nothing is a placebo, and four repositories would have
had one.

**Repositories declaring `typescript` for JavaScript.** The plugin's default
`files` is `**/*.ts` and `**/*.tsx`. Without a widened list the coach finds
nothing in `mihkel` or `servitium`. (`nomadtty` was the third such repository
when this was written; it is no longer governed. See
[007](./007-nomadtty-is-governed-by-upstream.md).)

**`jscpd` resolves from the project's `node_modules`.** Six repositories have no
`package.json`. Adding one — plus a lockfile, plus a Renovate surface — to a
repository with no JavaScript, for one duplication sensor, is disproportionate.
`line-count` is built in and still runs there, and it is the part of `generic`
that catches oversized YAML and Markdown.

## Consequences

- `.habit-hooks/config.toml` is a generated artifact, never hand-maintained,
  regenerated by `tooling/universe sync-baseline`.
- The audit checks that the generated config matches what the catalogue
  produces, and that changing `languages` changes both the config and the
  coaching instruction.
- `.habit-hooks/snooze.json` is the deliberate exception: it names the
  repository's own files, so it is repository-owned truth rather than policy.
- Generate a snooze baseline only after the sensor tools are installed.
  `habit-snooze --snooze` also snoozes the `incomplete-run` warning, which
  permanently hides the fact that a run was untrustworthy.
- The coaching layer stays advisory. None of this makes Habit Hooks a merge
  gate.
